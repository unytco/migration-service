## [Unreleased]

### Added

- **router: per-entry `published` visibility gate — customers-last migration surfacing (close-first).** Registry `DnaEntry` gains an optional `published` boolean (absent = unpublished, the safe default; validated boolean-or-absent at load). It is **HONORED by `/v1/update-check`** (`furthestTargetOf` now returns the deepest proven target that is *also* `published:true`, skipping/falling back past an unpublished one) — so a registered-but-unpublished successor is invisible to the app's upgrade banner (`has_upgrade:false`) — and **IGNORED by `/v1/migrate` + `/v1/migration-options`** (`reaches` / `sourcesReaching` unchanged) — so the headless server open can fetch the successor's close package *before* it is surfaced to customers. This splits the single `upgrade_targets` edge (which formerly both served the fetch and drove the banner) into two independently-gated jobs: the automation script writes a routing edge `published:false` at Stage 3.5, then flips `published:true` at Stage 7.1 once the whole fleet has migrated. Additive + backward-compatible — the gate lives entirely in `furthestTargetOf` (handlers/worker untouched), and the `published:false` default keeps a chain root (never a target) inert. Registry + handler tests pin both halves: migrate serves an unpublished target while update-check hides it, and publishing flips the banner on.
- **router: local-testnet mode (local-testnet task 02).** A separate local entry point (`src/index.local.ts`, run via `npm run dev:local` → `wrangler dev -c wrangler.local.toml`) loads a gitignored `registry.local.json` (start from `registry.local.example.json`) with `http://` notary URLs admitted (`Registry.load(..., { allowHttpNotaries: true })`), so a local registry can name plain-http daemons on container IPs. The deployed entry point (`src/index.ts`, `wrangler.toml`) keeps the strict https-only load and never even contains the relaxation — a test pins that an options object without the flag still rejects http. Runtime env comes from the checked-in `.dev.vars.example` (bearer token; CF-Access creds deliberately absent — the router only adds those headers when both are set). New optional `GITHUB_RELEASES_URL` env (never set on the deployed Worker) points the build axis at a local artifact server speaking the GitHub releases JSON shape, so a UI-release rehearsal can see its local patch build; the migrate flow never touches GitHub either way. Editing `registry.local.json` under `wrangler dev` hot-reloads (bundled-JSON watcher — verified live).
- **router: `latest_build.assets` — the release's downloadable installers, for the in-app updater (release-patterns task 07).** `/v1/update-check`'s `latest_build` now carries the release's assets (GitHub `name` + `browser_download_url` + `digest` → `name` + `url` + `digest?`), so the app's same-lineage "Update now" can pick this platform's installer and download it directly instead of routing the user to the release page. The router stays **platform-agnostic** — it passes every installer through and the app selects its own OS/arch; it has no business knowing a `.dmg` from a `.deb`. `digest` (GitHub's `"sha256:<hex>"`, absent on older releases) lets the app catch a truncated or corrupt download before handing an installer to the OS; it is **not** a defense against a compromised release, since it rides the same response as the URL. Malformed asset entries are dropped; a release with none yields `[]`. Additive + backward-compatible — a caller that ignores the field is unaffected, and the assets ride `latest_build` (single-lineage), so they can never name a migration release.
- headless-migrator: the verify step cross-checks the committed agreement state (via the DNA's `get_opened_agreement_state`) against the fetched close package.
- **headless-migrator: new Rust crate — the headless server-agent migration driver.** A standalone `clap` + `ham` binary (sibling of `notary-daemon`, same published-`rave_engine` + `ham` pins) with four modes: `status` (probe report: old chain closed · package fetchable · new chain opened), `close-service` (supervised: drop fees if owed → `prepare_closing_summary` → collect M-of-N via the parameterized policy → `close_agent_chain`), `open-service` (supervised: wait out gossip for the package → fresh membrane proof for the carried key from the target joining service → `install_app` with the package as `init_properties` (the DNA's `init` opens the chain) → verify), and `verify` (new-chain ledger vs the close summary, per-field). Each supervised service is probe-first + idempotent and exits 0 only on success (systemd `Restart=on-failure` drives the loop; no overall deadline). Operates on an already-carried agent key. Unit-tested against a mocked conductor seam (M-of-N policy with seeded RNG, probe→next-step incl. partial close, close/open no-op idempotency, `no_close_found`-keeps-waiting, bounded too-early-GD give-up, verify mismatch reporting); the full close → carry → open → verify arc + restart drills are a gated `tests/live_roundtrip.rs` (release-time). Writes a machine-readable state file for the `automation/` report collector; logs to journald.
- headless-migrator: wired into the repo `flake.nix`/musl toolchain and CI (`ci.yml` `agent` job: fmt + clippy + test, mirroring `notary-daemon`).
- notary-daemon: build-only `flake.nix` providing the musl cross-toolchain for the static deploy binary.
- router: `GET /v1/update-check?current_dna_hash=` — forward successor lookup so an app can detect a newer network and get its download link
- router: optional `release_url` field on registry DNA entries (surfaced by `/v1/update-check`)
- **router: two-channel `/v1/update-check` — a `latest_build` answer beside the migration answer.** Given an optional `app_version`, the router resolves the newest *published* GitHub release on the caller's own lineage (`latest_build`) so a UI-only release (which adds no DNA and no registry entry) is still detectable. Published = not draft, not pre-release, tag exactly `vMAJOR.MINOR.PATCH`; GitHub is the sole source of truth (the pre-release flag is the only control), resolved server-side behind a per-lineage Cache-API rate shield (new `builds.ts`, injected fetch + cache so the handler stays unit-testable). A migration `target`'s download link now forward-resolves to the newest build of the *target's* lineage, falling back to the recorded `release_url`. Additive + backward-compatible: a caller that omits `app_version` gets byte-identical behaviour, and any GitHub failure degrades to exactly that (still 2xx, migration answer intact).
- notary-daemon: gated live round-trip test (`tests/live_roundtrip.rs`, `cargo test --test live_roundtrip -- --ignored`) — the real daemon + real `ham` against a live conductor with a closed agent; locks the served package decoding with the same `rave_engine` types the app consumes (run command in the file header)
- **Skip-version migration routing + single-landing close target (M14).** The router routes a *direct* skip across more than one DNA generation, not just one hop: registry entries carry `upgrade_targets` (validated at load as registered, dup-free descendants), and reachability is computed over that forward graph — `GET /v1/update-check` returns the *furthest* reachable target (+ its `release_url`), `GET /v1/migration-options` lists every source that reaches a given target, and `POST /v1/migrate` discovers the agent's source DNA, rejects a `to` it can't reach, and threads the close's bound `target_dna_hash` through. The headless close binds to one configured successor — `MIGRATION_AGENT_TO_DNA` (`to_dna`) is required (the close service fails fast if unset) and is passed to `prepare_closing_summary(target)`; a target outside the source GD's `upgrade_targets` is a terminal hard-stop, never a retry.

### Changed

- **headless-migrator: GD-wait exhaustion now reports a config fault, not a raw genesis error, and the open loop is mock-drivable (local-testnet B91).** When the successor GlobalDefinition never gossips to the migrating target within the wait budget, the open service fails with an actionable diagnosis (`v2 GD never gossiped … check the successor DNA hash / registry and the target's Holochain+network config`) instead of the bare `No Global Definition found` genesis error. A `Connector` factory-trait injection lets a `MockConductor` drive the open loop, added a fleet-free negative rail test (`tests/open_service.rs`).
- Adopt published `rave_engine` 0.7.0 (`headless-migrator` + `notary-daemon`): headless-migrator drops its local `OpenedAgreementState` wire mirror for the crate type; notary-daemon now preserves the `AgreementCarryForward` `locked` field when serving a close package (on 0.6.0 it was dropped, which would fail a lock-carrying migration at signature verification).
- headless-migrator: DNA migration errors classify by typed `[MIGERR:<CODE>]` code first, English substring only as a fallback — a validator reword no longer silently reclassifies an error.
- **Upgrade to Holochain 0.6.2-rc.0 + `rave_engine` 0.6.0** (`headless-migrator` + `notary-daemon`) — the workshop-wide 0.6.2-rc.0 bump; this repo was the gap in the task-17 bump.
- **headless-migrator: install the successor with the package as `init_properties`, retiring the `migration_init` zome call (HC-795).** The open service installs the carried key WITH the fetched package as the alliance role's `init_properties` — the DNA's `init` opens the chain at genesis — then drives `init` via the first `verify_if_migrated` call and verifies. The post-install `migration_init` call, the first-zome-call ordering window (the in-agent guard + the systemd gate's ordering rationale; the gate itself stays as an open-completion gate), and the non-fresh-chain uninstall/reinstall recovery all go away; the open-side probe is now presence-only. A too-early install (the successor GD not yet in effect) is retried under a bounded `MIGRATION_AGENT_GD_WAIT_TIMEOUT_SECS` deadline (default 30 min) instead of forever — including when the verdict surfaces from the admin install/enable call itself (`ignore_genesis_failure: false` + `init_properties` can raise it there): install errors route through the same init-error classifier, so a too-early GD at install lands on the bounded deadline and a terminal verdict is the same hard stop, never an unbounded retry. And `status` is read-only in the strong sense: a new-server `status` makes **no zome call** (the first zome call on an `init_properties` cell would itself drive `init` and open the chain outside the supervised open flow) — `new_chain_opened` is reported from the open service's persisted signal (stamped as soon as `init` has driven the open), gated on a bounded admin-only presence probe. The GD-wait budget's first-too-early stamp is **write-once** in the state file: an interleaved `status`/`verify` rewrite can neither erase it nor renew the budget (the caller carries it forward, and `State::write` backstops any writer that forgets — like the `safe_to_teardown` latch guard).
- **Breaking — `rave_engine` pinned to the published `0.6.0`** — the skip-migration shape: `MigrationConfig.upgrade_targets` + `opening_predecessors` (was `opening_notaries` / `opening_threshold`), and `SummaryStatePayload`'s `source_dna_hash` / `target_dna_hash` split. `notary-daemon` + `headless-migrator` consume it from the registry (no git pin); the daemon reads the served package's `source_dna_hash` and surfaces the bound `target_dna_hash`.
- **Breaking — router: the `/v1/migrate` unregistered-pair reject is now `unreachable_target`** (was `not_registered_predecessor`) — it fires when the discovered source DNA has no forward path to the requested `to`, covering the no-edge and the multi-hop-unreachable cases alike.
- router: `/v1/migrate` error aggregation hardened — a config/daemon fault (a wrong-cell `internal`, a malformed package, or a zero-notary source) is surfaced as a 5xx `internal` (keeping its diagnostic details) rather than masked as a 503 outage by a co-occurring transient, and a wrong-cell/malformed response from one of a source's daemons now falls through to its sibling daemons instead of abandoning that source.
- **Breaking — the daemon is now the fetch-only service of the close-time M-of-N flow; it has no signing capability of any kind.** `POST /v1/notarize` (read + validate + sign) is replaced by `POST /v1/fetch-close`, which serves the agent's committed closing summary — the three-field package `{ payload, notary_signatures, close_action }` — via the read-only `read_predecessor_close` extern, so the migration-service can hand it to that agent to apply as install-time `init_properties` on the successor DNA. The `too_new` error code and the freshness window are gone from the API; the close's own collected signatures carry the trust
- notary-daemon: `/healthz` is healthy only when BOTH the conductor answers (`ping`) and the app cell answers (a `whoami` zome call) — either failing returns 503 with a distinct message (`conductor unreachable` vs `app cell unresponsive`)
- router: `/v1/migrate` forwards the daemon's three-field package verbatim (was `{ payload, signature }`); candidate notaries are tried in per-request RANDOM order (stateless load-spreading; injectable `rand` keeps tests deterministic); transient failures still fail over, hard stops still return immediately
- router: registry notary entries now pin the daemon HTTP API version (`"api": "v1"`); startup validation requires an `https` url and a supported `api` on every notary entry — a deficient entry fails at startup, never at request time
- notary-daemon: `rave_engine` pinned to the published release carrying the close-time M-of-N wire types (`ReadCloseResponse`, `NotarySignature`, `chain_top` payload)

- notary-daemon: re-pin `rave_engine` to the current migration shape (`a57bfc81` — agent-bound `SummaryStatePayload` + `SummaryState.agreement_carry_forward`); the prior lock (`221af08`) predated both, so the daemon signed/decoded a stale payload shape the deployed DNA validator would reject
- router: registry now rejects a fork (two DNAs upgrading from the same predecessor) so forward lookup is unambiguous

### Fixed

- **headless-migrator: the migrating install now applies the network's DNA properties — the cell lands on the network's DNA instead of an isolated one.** The open service installed the carried key with a role modifier carrying only the network seed, so the successor cell genesised with nil `properties` while every other agent on the network carries the release's (`progenitor_pubkey` / `joining_server_signer`). Properties are hashed into the DNA hash, so the migrated server sat on a *different* DNA than the network: its own empty DHT, no peers, no gossip, and an `init` that could never resolve the successor Global Definition (the "No Global Definition found for current timestamp" loop, observed live on a fleet). The joining service already serves them at `GET /join/:session/provision` as `dna_modifiers.properties` — the same values the fleet's other installers inject from `release.json` — so the open service now carries that field through to the role's modifiers alongside the seed. Held as `YamlProperties` (order-preserving) rather than a sorted JSON map, since the properties are msgpack-encoded into the hash and a re-ordered map is a different DNA. The cell is now also **held to what the migration is for**: `install_app` returns the provisioned `CellId` (the conductor already hands it back) and an already-installed app's is read admin-only (no zome call) on the restart path, so the open service hard-stops with an actionable message whenever the cell isn't on the `to_dna` being migrated to — naming both hashes and the three inputs that decide them (joining-service modifiers, happ bundle, target DNA), and ordered diagnose-then-act so an operator never uninstalls a correct cell when the wrong input was the target. The **agent** half is checked too: a node running several migrating apps off one shared carried lair can land the right DNA under the wrong key, which a DNA-only check waves through. A mismatch now fails in one clear line instead of surfacing hours later as a GD that never arrives, on a fresh node and on one a pre-fix binary already installed on the wrong DNA alike. Where the cell can't be read at all the check is skipped (logged, never a hard stop): "absent" and "present but unreadable" are both *unknown*, and raising the latter would convert a permanent condition into an unbounded retry — so that state is genuinely uncovered by the guard, not merely deferred.
- **headless-migrator: a rejected membrane proof is now terminal, not an infinite retry.** `genesis_self_check`'s four verdicts (`Membrane proof required` / `Signer is not the authorized progenitor` / `Membrane proof is not for this agent` / `Membrane proof signature is invalid`) matched nothing in the init hard-failure table, so they fell through to the unbounded transient arm. The path was unreachable while the migrating install produced a property-less DNA — the gate is skipped entirely when `joining_server_signer` is unset — so applying the network's properties (above) is exactly what makes it live. A joining-service signer mismatch would otherwise spin forever emitting nothing but "transient failure, retrying".
- **router: `/v1/migrate` now normalizes a byte-array `target_dna_hash` (local-testnet D7).** The handler accepts a DNA hash arriving as either a base64 string or a raw HoloHash byte array before comparing it to the registry's b64 hashes, and applies the same to `source_dna_hash` — closing a fail-open where a non-string source hash skipped the mismatch check. A valid in-app close package (whose notary-relayed hashes are raw bytes) no longer 500s, so the migration open proceeds.
- notary-daemon: add a wire round-trip smoke (`verified_envelope_round_trips_into_migration_init_request`) locking the daemon `Verified` envelope ⇄ app `MigrationInitRequest` encoding, and update the test fixtures to the agent-bound payload shape; 9 daemon tests pass against the re-pinned deps
- notary-daemon: `/v1/notarize` now parses `agent_pubkey` via `AgentPubKeyB64::from_str` instead of serde `Deserialize` — holo_hash's B64 serde does not round-trip its own string form (reads the chars as raw bytes → `BadSize`), so every real router call was rejected as `400`. First compile against the real `rave_engine`/`ham` deps; 8 daemon tests pass (also fixed an invalid hand-typed test fixture).
